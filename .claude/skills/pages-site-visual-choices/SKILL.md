# 本站视觉与交互选择

本技能记录 moss 在本项目里已经确立的界面偏好与已定取舍，提出方案、做原型与验收前照此执行。具体页面契约以 AGENTS.md 第五节为准，这里只放“怎样提方案、怎样判断”。

## React Bits 复刻

- moss 点名某个 React Bits 组件（Line Sidebar、Star Border、Flex Carousel、Gradual Blur、Drift Wall 等）时，先从 GitHub `DavidHDev/react-bits` 取原版源码，按原版默认参数移植；“差不多”的近似（如随手的 8px 位移、缩小版）会被判“差远了”。只在 moss 明确选择处偏离（如品牌粉、方向）。
- 不得不偏离原版时（如 Topography 随画布宽高比拉伸），按原版在参考屏（1440×900）上的实际观感反推新数值，并说明来由；moss 会追问“是 reactbits 默认尺寸吗”。
- 视觉或布局问题先给基于 React Bits 的候选，只讲信息架构的方案（折叠、横卡、详情页）会被判“太俗了”。候选临时注入页面，发桌面与手机（375px）截图；触屏效果优先，只靠悬停或光标的效果在触屏上不算数。
- 比较候选时用站内真实内容渲染：全部精选海报（2026 年 41 张）及其真实比例。有些组件的几何随数量变化（Circular Carousel 的半径随卡数增大，41 张时圆柱与全景几乎拉平），默认 10 张的演示会误导。
- 内置浏览器截图可能比 DOM 变化慢一帧，判断前再截一次。

## 控件与材质

- 所有可点的胶囊与圆形按钮是同一类组件（2026-10-04 定）：`--control` 40px、文字 13px，`--control-pad` 20px，内嵌小圆与图标占 `--control-inner` 24px、距边 8px 同心；工具栏 56px、圆角 28px；文字链接保持 44px 行高。
- 图标按文字大小定，不按按钮大小（14px 汉堡图标配 13px“筛选”）。胶囊内的圆形元素四周内距相等，从可见外缘量（边框算在内）。
- 带 `overflow:hidden` 的文字容器若 `line-height:1` 会裁掉中文字顶，裁切容器的行高给到约 1.4。
- 所有胶囊共用同一材质：换色或由脚本生成的胶囊同样要有 Specular Button 反光环与随鼠标的光，只改颜色令牌；所有鼠标光晕共用一套追踪与光照逻辑。
- 鼠标光效只分两种（2026-10-06 moss 定）：活动卡片一种（品牌四色、满亮度光带，鼠标在卡片上时光带一直指着鼠标，无底环）；其余胶囊与圆形按钮另一种（白光，中间最亮 68%，鼠标在按钮上时停到对角，自带底环）。新增的可点控件归入后一种，不另造第三种，也不必把两种合成一种。详情卡片（屏宽 700px 以上的卡片模式）属于活动卡片那种；手机上卡片全屏、没有边框，不加光环。
- 触屏设备上光效随手机晃动（glass-effects Q2–Q3，2026-10-06 定）：moss 没选“常亮、随倾斜转”，选了“只在晃动时闪亮”——倾斜速度超过每秒 15° 时屏幕上所有光带一起亮起、朝向倾斜方向，停下约 1 秒渐暗；iOS 不加开关控件，第一次点按时请求授权，拒绝后本次访问不再问。
- 站内面板都是磨砂玻璃，详情卡片也一样（glass-effects Q1，2026-10-06 选了“卡片磨砂玻璃”，没选背景更透、头图糊底或飞入动感模糊）：卡片约五成深色加 28px 背景模糊，遮罩约五成深色加 6px 模糊。新增浮层沿用磨砂材质，不做不透明底。
- 清单收起行平放（2026-10-06）：卡片不再原地展开后，Accordion Gallery 的 8° 倾斜被判“不太需要”。原版效果失去作用时提出去掉，而不是保留。

## 动效节奏

- Card Nav 曲线（`src/lib/motion.ts` 的 `EASE`）的 Web Animations 一律用同一文件的 `eased()` 写（2026-10-09，event-filters L2）：曲线写成关键帧、延迟写成开头停住、关闭写成反序的正向播放，Safari 才把它们交给合成线程；直接写 `easing: EASE`、`direction: 'reverse'` 或带 `delay` 的动画在 Safari 里留在主线程，地形每帧在画、点按时页面在重渲染，弹层与面板就顿（moss 报“bottomsheet 弹出弹入很卡”的原因）。曲线、时长与样子不变，改写法前后在同一时刻暂停截图逐像素比。活动详情各区与清单行还在用 `EASE`（event-filters Q4 没选，另提）。
- 整站动效克制：弹层与面板统一 Card Nav 节奏（0.4s power3.out、上移 50px、间隔 0.08s）；色块扫入、逐行旋转一类被判“太花里胡哨”。
- 来去的小元素不能显得被裁切：整枚从 0.8 缩放淡入、相邻元素平滑让位；退出用 0.3s power2.inOut。每个增减状态（包括“清空”）都要有过渡。
- 掉帧与流畅度（motion-performance，2026-10-06 定，2026-10-09 改）：不拿效果换流畅。10-06 自称“看不出差别”的几处——被遮罩盖住的行停止磨砂、遮罩只动透明度、筛选面板期间地形停住、高刷屏地形限 60 帧、就绪时跳过收起过渡——moss 一看就判“优化掉了样式、很多地方的模糊掉了、方向不对”，10-09 全部改回（Q27、Q28）；三轮手指滚动测试里改样子的做法（减小模糊半径、去掉行磨砂、滚动时暂停磨砂）也都被判“样子不行”。“看不出差别”要由 moss 看过才算，凡是会改变模糊、过渡或动画的优化都先拿方案问。moss 认同的方向是图片大小（按显示尺寸选档、省下载与解码），性能工作以此为主。各类设备、各个场景都会被问到流畅度，改动画、玻璃或逐帧脚本后，按 moss-browser 的测速做法（本机预览注入测速脚本、逐项关掉各部分）在有界面的 Chrome 里对比，并确认没有脚本错误。

## 首屏海报墙（hero-mobile，2026-10-04 定）

- 首屏要的是动感与氛围，不是把单张海报做平：把透镜调到中间海报永不弯折的方案被判“太朴素”；从 19 种 React Bits 形式里，moss 先选 Morph Slider，最后定了 Drift Wall。
- 海报要看得清：原版遮罩让墙半透明、等高线透过海报，被判“太过于透明”；墙中部必须不透明，四周与上下用柔和渐隐收边，不能硬切。
- 不要整齐划一：卡片固定同一宽度、宽屏列数越来越多被判“海报过多”，8 列也嫌多。现行为列宽按倍数循环、卡片为正方形（2026-10-05 由按海报原比例定高改来），1440 宽 6 列，更宽的屏幕整面墙等比放大。
- 每列都要能展示全部海报：手机上屏幕只露出约 2 列、一半海报到不了中部时，moss 先选整面墙在屏幕平面内斜转 +15°（所有宽度）并加卡内视差，验收时又要求“每列按一条长列表渲染”——全部海报排成一条列表，每列像无限轮播一样循环整条列表、起点错开（第 1 列 1–7、第 2 列 8–14……），不要按列轮流分配海报；每列海报变多后远离舞台的复制品设为不渲染，并用 CDP 把 CPU 降速 4 倍对比改动前后的帧率；卡内视差要明显到能展现整张海报（海报不裁切铺满卡宽，卡片漂过舞台一次就从顶平移到底、横版从左到右），沿用清单的 1.25 倍小幅位移被判“不够明显”；首屏是氛围，完整活动在清单。改首屏几何时先实测手机上有多少海报能到屏幕中部，作为事实给 moss。
- 斜转整面墙后，墙面要按斜转后的舞台范围（宽·sin + 高·cos）加长，否则宽屏的上下角会露空；`scripts/check_hero.mjs` 断言这一点。
- 首屏不放重复信息：日期统计与精选信息都已去掉；首屏与清单之间不加分割线，海报墙延伸到“活动清单”标题上沿。
- 触屏上点按海报直接打开该活动的详情（2026-10-05 起，原为跳到清单）；悬停提亮、停列只属于鼠标，手指按住不能让墙停下。
- 加载（motion-performance Q7，2026-10-06 定）：首张海报（LCP）优先于首次绘制。首屏墙脚本排在地形脚本之前、hero.css 内联，手机慢速配置下首张海报早约 0.4s、首帧晚约 0.4s，moss 选了保留；不要为提前首帧把脚本顺序或外链样式改回。舞台上的海报按面积从大到小下载（同配置下 LCP 4.4s → 2.6s，不影响首帧）；首屏墙每个文件只下一档，400px 档要盖住最宽的列（360px 在 1 倍屏最宽的列上会放大），所以 2 倍以上的手机仍用 720px 档、省不了流量。改加载顺序、版本或脚本顺序前，按 FCP、LCP 分项对比后再问 moss。

## 详情内容：内容即操作（2026-10-02 起）

- 操作直接放在内容上：点地址分享或复制、点小程序口令复制，右侧小图标提示；不另写“复制地址”“分享地址”“参考链接”之类的操作行。
- 未知或含糊的信息哪里都不显示、也不参加筛选：不写“未知”“尚不明确”“其它场地／时段／风格”或“DJ / MC 组合”这类占位，数据里直接留空；只保留 moss 选定的“暂无图片”与“当日暂无活动信息”。
- 已在摘要里出现的信息（艺人、风格）不在详情里重复；分区靠大标题与留白，不靠一排排细线或胶囊、按钮外壳。筛选胶囊只列大类、再下钻，不铺长平列表。
- 由来：moss 先后否掉了 Gooey Nav 分段胶囊、“分享地址”行、参考链接行、空的“风格参考”注记、“未知”单元格与密集的细线分区，判为杂乱、不够高级。设计详情面板或卡片时先从“内容即操作”和“标题＋留白”出发，定案前给截图。

## 活动详情（event-browsing Q20–Q26，2026-10-05 定）

- 详情不在行内折叠展开：moss 要求去掉“± 展开线”，清单每天第一条固定展开海报、其余收起且不可展开，点任何条目（含海报）或首屏海报都以 App Store 式过场（卡片从来源长成详情、海报随之放大、关闭时缩回来源）打开同页详情卡片层。新增入口或改清单交互时沿用这个卡片层，不再加行内展开。
- 详情卡片层的已定形态：手机全屏，桌面居中约 760px 宽；顶部是与展开行相同的裁切舞台；关闭为 ×、顶部下拉、Esc、桌面点遮罩与返回键；地址为 `#event-id`；原图预览只从详情头图打开。
- 动画验收：内置浏览器面板隐藏时截图停在旧画面，过场要在本机 Chrome `--headless=new`（GPU）里截中间帧，或请 moss 打开面板实看。
- 弱网（event-browsing Q34–Q36，2026-10-05 定）：过场与首屏也要在慢速、快速 4G 下实测，moss 会追问“弱网下 hero 会不会失效”。海报分原图与轻量版两版（生成与用途见 AGENTS.md 第四节），飞行用来源上已显示的那一版、落定后才换原图；首屏墙宁可先静止到屏幕上的海报到齐（最多 8 秒）也不漂着空白卡片（Q36 选了“到齐前先不漂”，没选再降清晰度）。改首屏或过场后用慢速 4G 逐秒复测屏幕上的海报到位比例。
- moss 验收前常要求先看实时预览：改完首屏后在内置浏览器打开本地页面并滚到顶部，再请验收。
